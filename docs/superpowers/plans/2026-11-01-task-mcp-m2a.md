# task-mcp M2a Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make lean as reliable as raw (no caused mistakes) on held-out Greenhouse postings, and report it with intervals, caused-mistake cases and a break-even line.

**Architecture:** Three small code changes in the generic package: the extractor gets plan-configured keyword hints, a config-aware cache key and token capture; eval can rerun a task subset without wiping other rows; the report gains reliability sections. Then the greenhouse example is tuned on the 20 M1 tasks, frozen, and scored once on a new `examples/greenhouse-holdout/` folder.

**Tech Stack:** Python 3.12+, uv, pytest, Ollama (`gpt-oss:20b` agent, `gemma4:12b` extractor). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-01-task-mcp-m2a-design.md` (approved 2026-11-01).

### Task 4: Grade extra flags; report reliability and break-even

**Files:**
- Modify: `src/task_mcp/grade.py` (`grade`)
- Modify: `src/task_mcp/report.py` (`arm_table`, new `wilson`, `caused_mistakes`, `break_even`; `render`)
- Modify: `src/task_mcp/cli.py` (`cmd_eval` row gets `extra_flags`)
- Test: `tests/test_grade.py`, `tests/test_report.py`

**Interfaces:**
- Produces: `grade(...)` result gains `extra_flags: list[str]` (sorted answer flag types not expected; does not affect `pass`). `wilson(k: int, n: int, z: float = 1.96) -> tuple[float, float]`. `caused_mistakes(rows) -> list[dict]`: tasks where raw passed and lean failed, each `{"task", "raw_label", "lean_label", "lean_final"}`. `break_even(rows, stats) -> str` (markdown lines).
- Report sections, in this order after "By arm": **Reliability** (caused-mistake count `N of M` with each case quoted; both-fail tasks listed separately; lean-only wins listed), **Savings** (unchanged), **Break-even**, **Extraction**, **Where lean and raw disagree**. Arm table gains a `Pass 95% CI` column (`lo–hi` as percents) and an `Extra flags` column (count of rows with any extra flag).
- Break-even text: `extraction per posting: T tokens (gemma4:12b), S s; saved per query: t tokens (gpt-oss:20b), s s; break-even after T/t queries by tokens, S/s by seconds`. Per-posting = stats sums / `extracted`. Saved = median raw minus median lean over tasks both passed (`tokens_in`, `seconds`). Missing token stats, zero extracted, or saved <= 0 -> that figure reads `not measured` or `never (no saving)`.
