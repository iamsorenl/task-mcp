# task-mcp Milestone 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a CLI that goes from a bloated read-only API to a lean, task-specific MCP server. The steps are record, propose, review, build, precompute, and eval. It is proven on Greenhouse job boards, with GitHub issues as the generality check.

**Architecture:** One editable `plan.yaml` drives everything. A shared runtime, `call_tool(plan, name, args, ...)`, applies tool shaping, field rules, and cached extraction. The generated server calls that runtime against the live API. The eval calls it in-process against recorded responses, for three arms derived from the same plan: raw, shaped, and lean. The agent loop is modeled on mcp-modelcheck's `agent.py`, rewritten here so it can take a pluggable responder and count tokens. It is not imported, because mcp-modelcheck's `run_task` is hardwired to its own `Replay`.

**Tech Stack:** Python 3.12+, uv, `mcp>=2.3,<3` (`mcp.server.mcpserver.MCPServer`, same as mcp-modelcheck), `ollama>=0.6.3,<0.7`, `httpx`, `pyyaml`, `jsonschema`, pytest.

**Spec:** `docs/superpowers/specs/2026-10-29-task-mcp-design.md`. Read the "Settled after the builder check" section; it overrides anything vaguer elsewhere in the spec.

## Review Focus

1. **A bad board token or 404 from the API.** The tool returns `{"error": "..."}` text and the agent can carry on. Nothing crashes. Test in Task 4.
2. **A posting with an empty description or no pay.** Extraction returns null or an empty list for missing facts and never invents a value. Test in Task 5 (fake model returns a quote not in the source, and it lands in `unverified`).
3. **The model returns invalid JSON or YAML** (extract or propose). Retry once with the parse error in the prompt. If it still fails: for extract, mark the item `extract_failed` and serve kept fields only; for propose, exit non-zero with the error. Tests in Tasks 5 and 6.
4. **An id is an int in recordings but a string from the agent,** e.g. `4012345` vs `"4012345"`. Replay keying normalizes all params to strings. Test in Task 2.
5. **A list response is huge** (Anthropic's board is about 9M chars). `propose` sends at most 3 sample items and a field inventory, capped at 20,000 chars, never the whole list. The agent loop truncates any single tool result over `max_tool_chars` and counts it. Tests in Tasks 6 and 8.

## Shared data shapes (all tasks use these)

**sources.yaml**
```yaml
name: greenhouse
base: https://boards-api.greenhouse.io/v1
endpoints:
  - id: list_jobs
    path: /boards/{board}/jobs
    query: {content: "true"}
    items: jobs[*]          # where the item list is (omit for single-object responses)
    item_id: id
  - id: get_job
    path: /boards/{board}/jobs/{id}
    item_id: id
    detail_of: list_jobs    # record() fills {id} from list items
seeds: {board: [anthropic, figma, vercel]}
max_details: 10             # per seed, for detail_of endpoints
```

**plan.yaml**
```yaml
api: greenhouse
task: "Screen job postings for fit against my preferences."
sources: sources.yaml
tools:
  - name: search_jobs
    description: "..."
    endpoint: list_jobs
    params:
      board: {type: string, required: true}
      query: {type: string, filter: title}            # case-insensitive substring on item field
      location: {type: string, filter: location.name}
    fields: {id: keep, title: keep, location.name: keep, absolute_url: keep}
    reasons: {content: "full HTML description; fetched per job by get_job"}
  - name: get_job
    endpoint: get_job
    params: {board: {type: string, required: true}, id: {type: string, required: true}}
    fields: {title: keep, location.name: keep, absolute_url: keep, content: {extract: description_facts}}
extracts:
  description_facts:
    html: true
    instructions: "..."
    schema:
      scope: {type: string}
      day_to_day: {type: list}
      experience: {type: list, quote: true}
      red_flags: {type: list, quote: true, enum: [seniority, experience_inflation, hours_996, location, pay, other]}
      pay_range: {type: string}
      onsite: {type: string}
```
Field paths not listed under `fields` are dropped. Items of `quote: true` lists are `{"text"|"type": ..., "quote": "..."}`.

**Recording index** `recordings/<api>/index.json`: `[{"key": str, "endpoint": str, "url": str, "params": {str: str}, "file": str, "status": int}]`.

**Tasks file** `examples/<api>/tasks.yaml`:
```yaml
preferences: "..."
red_flag_types: [seniority, experience_inflation, hours_996, location, pay, other]
tasks:
  - id: anthropic-4012345
    q: "Look at job 4012345 on board anthropic ... Reply with JSON {fit, red_flags:[{type,quote}]}"
    expected: {fit: "no", red_flags: [seniority]}
    checked: false    # true once Soren confirmed
```

### Task 5: Extractor with quote check and cache; precompute

**Files:** Create `src/task_mcp/extract.py`, add `precompute()` to `runtime.py`, `tests/test_extract.py`.

**Interfaces:**
- Consumes: `html_to_text` (Task 1); `call_tool` and the extractor protocol (Task 4).

### Task 8: Arms and agent loop

**Files:** Create `src/task_mcp/arms.py`, `src/task_mcp/agent.py`, `tests/test_agent.py`.

**Interfaces:**
- Consumes: `call_tool` (Task 4); `ollama_chat` return shape (Task 6).
- Produces:
  - `arm_plan(plan, sources, arm: "raw"|"shaped"|"lean") -> dict`.
    - **raw:** one tool per endpoint, named after the endpoint id, with params from path placeholders. Its rules keep every field path seen in the recordings, there are no filters, and it uses `items` passthrough.
    - **shaped:** the plan's tools and filters, with every field kept and no extract.
    - **lean:** the plan unchanged.
  - `tool_schemas(plan) -> list[dict]`, in Ollama function format.
